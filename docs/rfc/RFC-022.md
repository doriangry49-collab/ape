## 1. Context & Problem Statement

In Sprint 3, APE successfully solved the **Execution Engine** problem: establishing an 8-stage constitutional pipeline framework that decomposes monoliths, enforces policy-first gates, and produces deliverable files.

However, verified physical audit revealed a critical distinction:
- **Verification**: Confirms *existence* of expected deliverable files on disk.
- **Quality Assurance**: Confirms *correctness, executability, security, packaging, and performance* of generated deliverable files.

Without an automated Quality Assurance layer, execution decisions risk releasing broken, un-parseable, or insecure code to production.

RFC-022 introduces **Quality OS Foundation**: a language-agnostic, modular Quality Assurance Pipeline embedded constitutionally into APE's execution pipeline.

---

## 2. Quality OS Capability Matrix

Rather than viewing Quality OS as a flat list of checkers, Quality OS establishes a multi-dimensional **Capability Matrix**:

```text
Quality OS Capability Matrix
 ├── Correctness      : SyntaxValidator (AST parse, JSON format)
 ├── Executability    : ImportValidator (Module import sanity), PytestValidator, SmokeValidator
 ├── Environment      : DependencyValidator (requirements.txt / pyproject.toml check)
 ├── Packaging        : PackagingValidator (wheel / sdist build check)
 ├── Safety & Integrity: SecurityValidator (path traversal, eval safety), ArtifactIntegrityValidator
 └── Metrics          : Weighted QualityScore Engine & Trend Analytics
```

---

## 3. Pipeline Topology

The Constitutional Execution Pipeline is expanded from 8 stages to **9 stages**. `QualityAssuranceStage` is inserted strictly between `VerificationStage` (existence check) and `ExecutionEvidenceStage` (immutable audit logging).

```text
1. ExecutionPlanStage        (Goal & Milestone DAG generation)
2. PolicyCheckStage          (Fail-closed governance policy validation)
3. CapabilityCheckStage      (Environment snapshot & tool detection)
4. TaskExecutionStage        (State machine governed task execution)
5. VerificationStage         (Deliverable existence check on disk)
6. QualityAssuranceStage 🌟 (Modular Quality OS Capability Matrix evaluation)
7. ExecutionEvidenceStage    (Immutable Merkle evidence bundle generation)
8. ExecutionPersistStage     (State update & append-only audit persistence)
9. ReleaseDecisionStage      (Final release gate: Policy + Verification + Critical Quality + Audit)
```

## 4. Core Quality OS Contracts & Data Models

### 4.1 `ValidationStatus` Enum
```python
class ValidationStatus(str, Enum):
    PASS = "PASS"
    WARN = "WARN"
    FAIL = "FAIL"
    SKIP = "SKIP"
```

### 4.2 `ValidationContext`
```python
@dataclass
class ValidationContext:
    project_root: Path
    topic_slug: str
    deliverables: list[str]
    dry_run: bool = False
    metadata: dict[str, Any] = field(default_factory=dict)
```

### 4.3 `ValidationResult` (with Weighted Score & Critical Fail-Closed Trigger)
```python
@dataclass
class ValidationResult:
    validator_name: str
    status: ValidationStatus
    score: float       # 0.0 to 100.0
    duration_ms: float
    is_critical: bool = True  # Critical validators MUST PASS for release
    weight: float = 1.0       # Weight for overall QualityScore calculation
    findings: list[str] = field(default_factory=list)
    warnings: list[str] = field(default_factory=list)
    errors: list[str] = field(default_factory=list)
    artifacts: list[str] = field(default_factory=list)
```

### 4.4 Language-Agnostic `Validator` Protocol & Discovery Registry
```python
class Validator(Protocol):
    @property
    def name(self) -> str: ...

    @property
    def is_critical(self) -> bool: ...

    @property
    def weight(self) -> float: ...

    def validate(self, context: ValidationContext) -> ValidationResult: ...
```

`ValidatorRegistry` enables discovery by language pack (`python`, `go`, `rust`, `react`).

## 5. Fail-Closed Rules & Release Hardening

1. `QualityAssuranceStage` computes `QualityReport` using weighted scoring:
   $$\text{OverallScore} = \frac{\sum (\text{score}_i \times \text{weight}_i)}{\sum \text{weight}_i}$$
2. **Critical Fail-Closed Trigger**: If ANY validator marked `is_critical == True` returns `ValidationStatus.FAIL`, `quality_audit_passed` MUST evaluate to `False` regardless of `overall_score`.
3. `ReleaseDecisionStage` verifies that `ALL_CRITICAL_PASS` AND `overall_score >= 80.0` AND `verification_passed == True` AND `persist_receipt_valid == True`.
