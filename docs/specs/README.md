# Specs

This directory stores concise product and implementation specifications for the APE project.

Each spec captures the intent, requirements, implementation notes, tests, and acceptance criteria for a focused area of work. Specs are meant to guide implementation and review without replacing the architecture or roadmap documents.

## Naming Convention

Use the pattern `SPEC-####-short-name.md`.

Examples:
- `SPEC-0001-foundation.md`
- `SPEC-0004-workspace.md`
- `SPEC-0018-constitutional-pipeline-architecture.md`
- `SPEC-0019-resource-budget-model.md`

## When to Create a New Spec

Create a new spec when a piece of work introduces a clearly defined feature, subsystem, or architectural concern that should be documented before implementation. A new spec is also appropriate when a change affects behavior, interfaces, or expectations across multiple commands or modules.

## Reading Guidance

If a relevant specification exists in this directory, read it before implementation work begins.
